## 1. 产品目标与已确认约束

制作公开、免费使用的模型转换网站，源码托管在 GitHub，通过 GitHub Pages 发布。用户打开网址，导入模型和配套资源，预览内容，选择目标格式并下载转换结果。

总体目标是广泛覆盖市面上的各类三维模型，包括网格与场景、CAD、BIM、点云、地理三维数据和 Gaussian Splatting。格式逐步适配，首版优先广覆盖的可用转换路线，不宣称任意文件都能相互转换。

已确认决策：

| 项目         | 决策                                                                 |
| ------------ | -------------------------------------------------------------------- |
| 使用者       | 面向公众，访问者免费使用                                             |
| 产品形态     | 网页工具                                                             |
| 托管         | 只用 GitHub Pages，无独立转换后端                                    |
| 计算位置     | 访问者浏览器；不依赖开发者电脑持续在线                               |
| 依赖策略     | 免费开源方案，许可须适配公开分发与实际用途                           |
| 常见任务规模 | 通常小于 1 GB，实际可处理规模取决于访问者设备                        |
| 保留目标     | 几何、材质、贴图、单位、方向、层级；目标支持时保留骨骼动画和工程属性 |
| 表达转换     | 纳入近似重建，明确说明算法、损失和限制                               |
| 开发优先级   | 先接通常见类型，再完善需要专项开发的格式                             |
| 默认语言     | 简体中文                                                             |
| 首要浏览器   | 桌面 Chrome、Edge；Firefox 验证基础流程                              |

前期讨论的“科研自用、本机 Python/CUDA 服务、WSL2 研究引擎”已被公开 GitHub Pages 的方案替代，不作为部署前提。

## 2. 托管与执行边界

GitHub Pages 分发静态 HTML、CSS、JavaScript、WebAssembly 和必要程序资源。转换逻辑在浏览器中运行；Python、Blender、CUDA 和原生桌面 SDK 不作为线上运行依赖。

浏览器中的“本地处理”指访问者设备上的处理，不是开发者电脑处理。使用网站不要求安装本地服务。

GitHub Actions 仅用于检查、构建和发布静态网站，不承担用户转换任务。首版不增加账户、支付、模型云存储或共享后台任务队列。

SuGaR 不进入默认在线链路：其仓库许可证限定研究与评估用途，且官方完整流程涉及照片、相机位姿与原生运行环境。网站免费不等于公众任意用途自动获得研究授权。本项目首版采用可在浏览器中实现的采样和等值面提取方法。

## 3. 格式支持矩阵

下表是首版实施目标，不是当前已完成的能力。导入、导出、版本范围和内容类型分别登记，界面仅开放已经实现且通过验证的路线。

| 类别               | 首版输入                                                        | 首版输出                                           | 主要限制                                                                   |
| ------------------ | --------------------------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------- |
| 网格与场景         | OBJ、FBX、GLB/glTF、STL、PLY、OFF、3DS、DAE、3MF、AMF、WRL、3DM | GLB/glTF、OBJ、STL、PLY、OFF、3DM；实验性 FBX 导出 | 目标格式对动画、PBR 材质、层级等能力不同                                   |
| CAD/BIM            | STEP/STP、IGES/IGS、BREP、FCStd、IFC、DotBIM                    | 网格格式及关联工程属性文件                         | 首版 CAD 输出为离散网格，不提供精确曲面、参数化历史或完整 CAD/BIM 原生回写 |
| 点云               | PLY、PCD、XYZ、LAS/LAZ 1.0–1.3                                  | PLY、PCD、XYZ                                      | 当前选用的 LASLoader 不支持 LAS 1.4；不能静默误读                          |
| Gaussian Splatting | 标准高斯 PLY、SPLAT、SPZ                                        | 标准高斯 PLY、SPLAT                                | 目标属性集合不同，特别是高阶球谐和量化精度                                 |
| 3D Tiles           | 显式层级中的 GLB、B3DM 网格和 PNTS 点云                         | 按块导出对应模型；网格封装为单级 3D Tiles          | 首版不承诺复杂隐式层级、所有扩展、原生高斯瓦片及全量 LOD 重建              |

补充规则：

1. PLY 必须依据头部和属性区分三角网格、普通点云和高斯，不能统一按同一种模型处理。
2. DotBIM 是轻量 BIM 格式，不等同于 IFC，更不代表所有原生 BIM 工程文件。
3. 3D Tiles 是内容组织与流式传输规范，具体转换能力由瓦片内部内容决定。
4. 支持导入 FBX 不代表天然支持导出 FBX。FBX 导出使用带导出能力的 Assimp WASM 适配，并标为实验性，通过回读验证后开放。
5. 不能依据桌面 Assimp 的完整格式清单，直接声称其浏览器编译版本支持相同内容。
6. 原生闭源工程格式只在有适配器且经过实际验证后加入支持清单。

后续专项适配包括 OSGB、完整 CAD/BIM 原生回写、更丰富的瓦片类型和其他工程格式。OSGB 可研究基于 OpenSceneGraph/osgVerse 构建 WASM 读写桥接，不能把浏览器预览示例直接当成已具备转换能力。

## 4. 技术架构

### 4.1 技术栈与组件

| 模块           | 选型与职责                                                  |
| -------------- | ----------------------------------------------------------- |
| 页面与构建     | React、TypeScript、Vite                                     |
| 三维场景与动画 | Three.js；动画路线使用可保留骨骼、蒙皮与关键帧的独立通道    |
| 广覆盖网格导入 | AssimpJS、Online3DViewer 及 Three.js 加载器，按实际能力路由 |
| CAD            | OCCT 浏览器封装；首版处理导入和离散化                       |
| IFC            | Web-IFC；读取几何、构件关联与可提取属性                     |
| 点云           | 相应点云解析器及 LASLoader，限制已验证的文件版本            |
| 高斯           | Spark 解码与预览；保存解码后的原始属性数组作为导出来源      |
| 瓦片           | 浏览器侧解析器与显式层级遍历，正确处理空间变换              |
| 后台计算       | Web Worker，默认一个转换任务运行，其余本机排队              |
| 打包下载       | 浏览器 ZIP 工具，优先分块处理并及时释放缓冲                 |
| 发布           | GitHub Actions 构建并发布到 GitHub Pages                    |

Three.js、WASM、ZIP 等依赖在对应功能实现时接入。依赖版本通过锁文件冻结，避免相互不兼容的渲染器和加载器版本。

### 4.2 模块边界与最小接口

统一 `FormatAdapter` 适配器接口，提供：

- 能力声明：格式标识、扩展名、版本与内容类型、导入/导出能力、实验性状态。
- 文件检测：依据文件头与资源集合判断实际内容。
- 读取：返回场景、点云或高斯数据及元信息。
- 写入：返回文件集合、关联资源及转换报告。

中间数据按 `Scene`、`PointCloud`、`Gaussian` 分开组织，携带单位、坐标、层级、属性与源对象关联。不能把所有输入强制转为静态 GLB 再导出，否则会提前丢失动画、工程语义或高斯属性。

Worker 使用任务标识分发检测、读取、转换和取消操作，返回阶段、进度、产物或错误。取消长任务时可终止并重建 Worker，确保释放计算资源。

新增格式通过适配器注册，不为每一对格式单独重复开发完整转换器。路由优先选择能保留更多数据的路径，不仅以步骤最少作为依据。

### 4.3 浏览器资源与部署约束

- 使用单线程 WASM 配合 Web Worker，首版不依赖 SharedArrayBuffer 或需要特殊响应头的多线程运行。
- 重型引擎按格式加载，避免首屏一次加载全部引擎。
- 程序、Worker、WASM 与解码资源随站点分发，资源路径适配 GitHub Pages 仓库子路径。
- 模型使用浏览器 File/Blob 接口读取，不发送到远程转换服务。
- 不自动请求模型引用的外部资源；缺少资源时提示用户补充导入。
- 预览可以使用简化数据，导出必须使用转换原始数据，不能拿预览精度替代导出精度。

## 5. 用户流程与界面

使用单页工作台，围绕转换任务布局：

1. 导入文件、文件夹或 ZIP，保留目录与相对资源关系。
2. 自动检测主模型、内容类型和配套资源；存在多个主文件时由用户选择。
3. 展示三维预览、对象层级、基础规模、单位，以及动画或工程属性入口。
4. 按当前输入和适配器能力显示目标格式，说明实验性状态和数据变化。
5. 用户设置单位、方向、质量及必要的转换参数后开始转换。
6. 显示真实处理阶段和进度；不伪造算法无法提供的精确百分比。
7. 单文件直接下载，多文件结果打包为 ZIP，并附转换报告。
8. 支持取消、失败重试和连续导入下一任务。

不提供无效转换按钮，不通过改文件后缀伪装完成转换。未实现或不支持的路线显示原因。

## 6. 数据保留与地理处理

### 6.1 保留策略

- 默认保留源数据单位、方向和层级；用户主动要求变换时才应用相应设置。
- 目标格式支持的几何、法线、UV、材质、贴图及动画尽量原生写入。
- GLB/glTF 与 FBX 的动画转换使用独立场景通道，避免静态模型中间层将其扁平化。
- 工程属性按对象关联保存。目标格式不能表达的属性写入 `metadata.json`，并在报告中明确说明属性存放位置。
- 附带属性文件不等于目标模型原生保留全部工程语义。
- CAD 曲面离散化、高斯属性截断、动画烘焙和坐标变更都要记录；不能把“转换成功”写成“无损”。
- 对无法读取的属性如实列出，不能将未提取的信息声称已经保留。

### 6.2 3D Tiles 与坐标

- 解析父子节点空间变换及瓦片自身定位信息，转换中保留高精度坐标。
- 需要渲染时使用局部原点，导出时保留或记录与原坐标的对应关系。
- 每条分支选择最细可用内容，避免同一地区的父子 LOD 同时导出造成重复。
- 默认分块下载，不自动把整个场景合成单一模型。
- 网格封装为单级 3D Tiles 时写入有效包围体和内容引用，不宣称自动生成了完整切片金字塔。
- 输入缺少地理定位时使用局部坐标，不凭空赋予经纬度或坐标系。

## 7. 实验性表达转换

实验路线独立于普通格式转码，界面和报告明确标注其性质。

| 路线        | 首版方法                                                 | 需要说明的变化                                       |
| ----------- | -------------------------------------------------------- | ---------------------------------------------------- |
| 网格 → 点云 | 按三角面面积进行表面采样，读取 UV/材质颜色               | 连续表面变成离散采样                                 |
| 网格 → 高斯 | 表面采样，估计沿表面的尺度与方向，生成高斯属性和基础颜色 | 不会自动恢复源模型没有的真实光照或视角相关外观       |
| 点云 → 网格 | 法线估计、距离场构建、等值面提取                         | 稀疏、噪声和遮挡区域可能出现缺失或错误表面           |
| 高斯 → 网格 | 高斯密度场等值面提取                                     | 得到的是近似密度外壳，不承诺等于真实物体表面         |
| 高斯 → 点云 | 导出中心位置及可映射属性                                 | 普通点云不能完整保留高斯形状、不透明度和视角相关属性 |

重建默认采用低分辨率，允许用户调整质量。明确展示采样数量、处理规模和降级项。首版不包含照片训练、SuGaR、CUDA 或服务端研究流程。

## 8. 文件规模与失败处理

- 默认一次运行一个转换任务，其他任务在访问者本机排队。
- 单任务导入总量，以及 ZIP 解压后的总量，上限均为 1 GiB。
- 超过 256 MiB 提示可能有较高内存需求；这不是浏览器能成功处理全部此类文件的保证。
- 尽量分块解析，减少缓冲复制，处理完成、取消和失败后释放模型、纹理、WASM 与 Blob URL。
- 文件超限、内存不足、版本不支持、缺少贴图、路径无法解析、损坏数据和无可用路线分别给出具体提示。
- 刷新页面不会自动恢复内存中的模型文件；需要重新导入。不默认持久化用户模型。
- ZIP 校验目录路径和解压总量，避免相对路径越界与无界解压。

## 9. 开发阶段与交付物

### 阶段 0：项目初始化与设计归档（初始任务，已完成）

交付 React + TypeScript + Vite 基础工程、中文初始化页面、完整设计文档、README、MIT 许可证、忽略规则与依赖锁文件；完成类型检查和生产构建。

本阶段不代表格式矩阵已经实现，不创建远程仓库，不发布网站。

### 阶段 1：通用任务框架与常用网格转换

实现文件集合、资源解析、适配器注册、任务队列、取消/重试、预览和下载；优先接通 OBJ、GLB/glTF、STL、PLY。随后加入广覆盖导入和实验性 FBX 导出。

### 阶段 2：CAD/BIM、点云与高斯

接入 OCCT、Web-IFC、点云解析器和 Spark；实现关联元信息、动画保留通道、工程属性导出，以及矩阵内的点云和高斯转换。

### 阶段 3：有限瓦片与实验重建

接通显式层级的 GLB/B3DM/PNTS 读取、按块导出与单级网格瓦片封装；加入采样、距离场与密度场实验转换，落实各路线的质量说明。

### 阶段 4：公开发布

完成兼容性、资源路径、内存和网络行为检查，接入 GitHub Actions，发布首个可使用版本。公开格式清单以已验证能力为准。

### 后续迭代

OSGB WASM 桥接、更多瓦片内容、更高保真工程格式转换及其他模型格式通过后续适配器推进；每个新增路线都要有实际样例与读写验证。

## 10. 测试与验收

### 10.1 格式与保真验证

- 每条公开路线准备有许可证说明的真实样例，导出后重新读取。
- 检查几何形状、包围盒、方向、单位、UV、贴图、层级和目标格式支持的属性。
- 骨骼动画样例检查蒙皮、动画时长、关键帧和播放效果。
- IFC/CAD 装配样例检查对象层级和属性归属；记录无法提取或表达的内容。
- 单独验证 FBX 导出，避免以“产生了文件”作为成功标准。
- 使用已知几何体检查实验重建，报告偏差及结果规模。
- 分别验证网格 PLY、点云 PLY 和高斯 PLY 的检测和导出。

### 10.2 健壮性与坐标验证

覆盖中文和空格路径、嵌套目录、缺失贴图、损坏文件、不支持版本、压缩输入、取消、重试、内存不足、多级瓦片、地理坐标与 LOD 重复问题。

### 10.3 浏览器与发布验证

- Chrome、Edge 完整验收；Firefox 验证基础流程。
- 类型检查和生产构建通过。
- 仓库子路径下 Worker、WASM、动态模块和贴图均正确加载。
- 检查网络请求，确认用户模型与引用资源不被上传到远程服务。
- 已展示为“支持”的路线必须能实际导出并被对应读取器打开。
